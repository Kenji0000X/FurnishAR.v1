# FurnishAR alert / notification audit

| FILE / COMPONENT | CURRENT BEHAVIOR | PROBLEM | RECOMMENDED CHANGE | IMPACT |
| --- | --- | --- | --- | --- |
| app/layout.js | Global shell renders header, footer, page content, and cookie notice. | No centralized alert container existed at the app shell. | Add one shared notification area at the top-level layout. | Makes every page share the same alert surface. |
| app/FlashBanner.js | New banner component reads a flash message from storage and displays it globally. | Previously notifications were scattered and page-local. | Keep the banner as the single UI container for global alerts. | Consistent message placement and access across routes. |
| lib/flash.js | Stores notification payload with type + message and emits a browser event. | Alert system was fragmented and inconsistent across pages. | Use it as the single service API for showSuccess, showError, showWarning, showInfo. | One reusable notification API for all flows. |
| app/login/LoginChooser.js | Drives buyer auth, sign-in, sign-up, status text. | UI used ad hoc notice strings and no central alert event. | Route success/error/loading messages through the shared alert service. | Users get consistent sign-up/sign-in feedback. |
| app/account/BuyerAccount.js | Saves profile and signs out shopper account. | Success and error text were page-local and not shared globally. | Emit save/logout events through the central alert service. | Clear account status feedback. |
| app/portal/Portal.js | Handles store portal login, signup, signout, deletions, product actions. | Notice logic varied across actions and was repeated. | Consolidate all operational feedback into the shared alert service. | A single user-facing status pattern across the portal. |
| app/plan/ar-engine.js | Uses in-engine toast messages for AR / scanner guidance. | This is useful for immediate scanner feedback but not a centralized app alert system. | Keep contextual AR toasts, but route major user-facing states through the shared alert service where appropriate. | Scanner feedback stays contextual without breaking the global system. |
| public/styles.css | Has toast and status-banner styling, but no common alert system contract. | Visual treatment was split across ad hoc classes. | Standardize banner styles for info/success/error states and ensure mobile-safe placement. | Stronger consistency and accessibility. |
| app/admin/AdminGate.js | Uses page-level notice/error fields for approvals and login status. | Some admin flows still use local messages instead of global alerts. | Keep validation text near the field, but centralize important operational messages. | Higher consistency for critical actions. |
| app/portal/backend.js | Handles auth and API status. | Errors are returned as technical messages unless the caller formats them. | Continue converting backend errors into human-readable messages before calling the alert service. | Prevents leaking raw API details to users. |
